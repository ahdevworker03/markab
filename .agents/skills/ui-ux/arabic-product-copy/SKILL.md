# Arabic Product Copy Skill

## How This Works

When writing or reviewing Arabic product copy, follow this sequence:

1. **Identify the UI context** — Navigation, button, form label, error, empty state, dashboard metric, table header, or workflow action.
2. **Use practical business language** — Write for daily software use, not marketing.
3. **Keep copy short** — UI labels should be clear and concise.
4. **Preserve domain meaning** — Do not change business terms, statuses, or workflow meaning.
5. **Review tone** — The copy should sound calm, professional, and natural.

## Product Context

This product is an Arabic-first vehicle rental SaaS.

Users are:

- Business owners
- Rental office employees
- Operational staff

The copy should help them complete work quickly.

## Tone

Use a tone that is:

- Professional
- Direct
- Calm
- Clear
- Practical

Avoid:

- Marketing exaggeration
- Motivational language
- Exclamation marks
- Overly formal government-style Arabic
- Machine-translated wording
- Long sentences
- Vague success messages

## Language Style

Use clear Modern Standard Arabic suitable for software.

Keep it simple.

Avoid heavy classical phrasing.

Avoid casual slang unless explicitly requested.

## Success Messages

Success messages should be calm.

Recommended:

- تم حفظ التغييرات.
- تم إضافة المركبة.
- تم إضافة العميل.
- تم إنشاء الإيجار.
- تم تسجيل الدفعة.
- تم إكمال الصيانة.
- تم حذف السجل.
- تم تحديث الحالة.

Avoid:

- تم بنجاح!
- رائع! تم الحفظ
- لقد قمت بإنجاز العملية بنجاح مذهل

## Error Messages

Errors should explain what happened and what to do next.

Recommended:

- تعذر حفظ التغييرات. حاول مرة أخرى.
- تعذر تحميل البيانات. تحقق من الاتصال.
- هذا الحقل مطلوب.
- أدخل رقماً صحيحاً.
- تاريخ الإرجاع يجب أن يكون بعد تاريخ الاستلام.
- هذه المركبة غير متاحة في الفترة المحددة.
- لا تملك صلاحية تنفيذ هذا الإجراء.

Avoid:

- عذراً حدث خطأ ما
- أوه لا!
- خطأ غير معروف
- فشلت العملية!

## Empty States

Empty states should be specific and useful.

Structure:

1. State what is missing.
2. Explain the next action.
3. Provide action button if appropriate.

Examples:

```md
لا توجد مركبات بعد.
أضف أول مركبة لبدء إدارة الأسطول.
```

```md
لا توجد إيجارات نشطة.
ستظهر الإيجارات الحالية هنا بعد إنشائها.
```

```md
لا توجد مدفوعات مسجلة.
سجّل دفعة عند استلام مبلغ من العميل.
```

Avoid:

- لا توجد بيانات
- لا شيء هنا
- ابدأ رحلتك الآن

## Confirmation Copy

Use direct confirmation.

Delete/archive example:

```md
هل تريد حذف هذا السجل؟
لا يمكن عرض السجل في القوائم بعد الحذف.
```

Cancel rental example:

```md
هل تريد إلغاء هذا الإيجار؟
سيتم تحرير المركبة من هذا الحجز.
```

Avoid dramatic warnings unless the action is truly destructive.

## Arabic Formatting Rules

- Use Arabic labels consistently.
- Keep English technical terms only when they are product or developer-facing.
- Avoid mixing Arabic and English inside user-facing labels unless necessary.
- Use Arabic punctuation where natural.
- Keep numbers readable based on the app's existing formatting.
- Do not add tashkeel unless there is ambiguity.
- Avoid long text inside buttons.

## Review Checklist

Before accepting Arabic UI copy:

- Is it short?
- Is it clear?
- Is it professional?
- Is it specific to the workflow?
- Does it avoid marketing language?
- Does it avoid machine-translation style?
- Does it preserve domain meaning?
- Does it fit the available UI space?
- Does it work in RTL layout?

## Rules

- Do not change domain terms without approval.
- Do not invent new statuses.
- Do not make operational software sound like an advertisement.
- Do not use exclamation marks in normal product feedback.
- Prefer clarity over elegance.
