# Fix Vehicle Photo Serving — Milestone 2 AI Review Finding

---

## Summary

Fixed the vehicle photo serving issue found in the final Milestone 2 AI code review. Previously `PhotoResponse.url` contained the internal `storage_key`, and `MediaGallery` used it as `<img src>`, which could never load because there was no photo-serving endpoint. Now a dedicated authenticated serve endpoint returns the image bytes, the response `url` points to that endpoint (no storage key exposed), and the frontend loads photos through the existing generated API client + React Query infrastructure.

## Endpoint Added

`GET /api/vehicles/:vehicleId/photos/:id/serve` (authenticated)

- Reuses the existing `StorageProvider` / `LocalFilesystemProvider`.
- Returns the raw image bytes with the correct `Content-Type` (`image/jpeg` / `image/png` / `image/webp`), `Content-Length`, and `Cache-Control: private, max-age=3600`.

---

## Security Behavior

- **Authenticated-only**: the route is behind `authenticate`; unauthenticated requests → 401.
- **Organization isolation**: `serveVehiclePhoto` calls `ensureVehicleInOrg(vehicleId, orgId)` first; the photo record is fetched with `findPhoto(photoId, vehicleId, orgId)` which scopes by both vehicle and org. Cross-org access → 404.
- **Vehicle membership**: the photo must belong to the requested vehicle (not just the org) — enforced by the `vehicle_id` in `findPhoto`.
- **Soft-delete**: a `deleted_at` photo → 404 (not served).
- **No key/fs exposure**: the client only ever sees the serve path `/api/vehicles/{id}/photos/{id}/serve`; the storage key and filesystem path are never returned.

## Remaining Limitations

- Photos are served through a Blob fetch + object URL (the `<img>` tag cannot send the `Authorization` header, and the app uses bearer-token auth rather than cookies). This matches the existing document-download pattern and keeps the token out of URLs.
- `Cache-Control: private` avoids shared-cache leakage; a longer-lived cache would require a token-in-query or cookie-based photo CDN, which is out of scope.
- The serve endpoint is photo-only by design (the review finding concerned vehicle photos); customer/vehicle documents already had download endpoints and are unchanged.
